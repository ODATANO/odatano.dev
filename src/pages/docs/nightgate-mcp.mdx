# NIGHTGATE-MCP

`@odatano/nightgate-mcp` is a **Model Context Protocol (MCP) server** that puts NIGHTGATE, the attestation layer on Midnight, in front of AI agents. An agent anchors documents on-chain, proves zero-knowledge predicates over hidden document fields, manages disclosure grants and verifies against live contract state. Async jobs are polled the same way. All of it through plain MCP tool calls. The agent needs to know nothing about OData, Compact or Midnight.

Wallet lifecycle (connect, send, deploy) is **deliberately not exposed**: the agent gets a notary, not a wallet. Writing without a wallet session works through fee sponsoring: the agent builds locally, a sponsor pays.

## Highlights

- **22 tools** covering verify, prove, anchor, grant, sponsoring and jobs. That is the full NIGHTGATE attestation surface.
- **Clean negatives:** every verification tool returns `verified: false` when an attestation or proof is absent, never an error
- **Fee sponsoring:** `build_sponsorable_transaction` proves and signs locally, `sponsor_unbound_transaction` lets a sponsor pool pay. No wallet session needed.
- **Scoped agent access:** one `oda_…` key through the hosted gateway, or an `ngat_…` agent grant against a direct instance (tool allowlist, budget, pinned session)
- **Async job model:** anchor / prove / grant / sponsor tools return a job id; `get_job_status` polls until `succeeded` / `failed`
- **Zero-install:** ships a `nightgate-mcp` binary. `npx @odatano/nightgate-mcp` is enough.
- **Any MCP client:** Claude Code, Claude Desktop, Cursor, or a custom `@modelcontextprotocol/sdk` client

## Requirements

| Requirement | Version |
|-------------|---------|
| Node.js | ≥ 20 (`npx` fetches the server, nothing to install) |
| NIGHTGATE instance | ≥ 0.24.0 for MCP 0.6.x / 0.7.x (see the version matrix below). Not needed with the hosted API. |
| `@odatano/nightgate-tx` | ≥ 0.6.0, optional. Installed next to the server, only for `build_sponsorable_transaction`. Needs `NIGHTGATE_SEED_HEX`. |

The MCP line must match the NIGHTGATE server. From NIGHTGATE 0.16.0 on, content-tree leaves are salted. An older MCP omits the salt and the server rejects the call with 400.

| MCP | NIGHTGATE | Notes |
|-----|-----------|-------|
| 0.6.x / **0.7.0** | ≥ 0.24.0 | Current. Vault lineage 4 keys every record by attester and payload. `verify_attestation` takes `attesterId` + `payloadHash` (or a bound `documentId`), `verify_predicate` takes `attesterId`, `anchor_document` returns `attesterId`. `prepare_anchor_commitment` and `commit_document_anchor` are gone. 0.7.0 only renames the connection env vars to `ODATANO_ACCESS_*`. |
| 0.5.1 | ≥ 0.19.0 for width 32 | 32-slot vault via `compiledArtifactRef: 'attestation-vault-32'`. A 16-slot setup keeps working against 0.18.x. |
| 0.5.x | ≥ 0.18.0 | Parallel sponsoring channel (`sponsor_unbound_transaction`, platform pool id) and local building (`build_sponsorable_transaction`, `get_attester_identity`). |
| 0.4.x | ≥ 0.17.0 | Cross-server fee sponsoring, serial channel only (`sponsor_finalized_transaction`), `derive_token_type`. |
| 0.3.x | ≥ 0.16.0 (0.16.2 recommended) | Cross-root proofs, schema ids, per-field salts. Fails against 0.15.x and older. |
| 0.2.x | 0.15.x | Bytes equality and set membership on unsalted leaves. Fails against 0.16.0 and newer. |
| 0.1.x | 0.14.x | Anchoring, numeric field predicates, disclosure, agent provenance. |

The verification tools only read live contract state and work across the whole range. They just cannot express newer claim kinds on an older server.

## Getting a NIGHTGATE instance

With an ODATANO ACCESS key you need none. The hosted gateway at [api.odatano.dev](https://api.odatano.dev) is the default URL and runs NIGHTGATE on Midnight **preprod**. Sponsored writes on the platform pool are included; the verify lane and the prover keys under `/zk-config` are free.

For your own instance, the fastest way is the official Docker image published from the NIGHTGATE repo. No Node setup, no host app:

```bash
docker run -d --name nightgate -p 4004:4004 \
  -e ENCRYPTION_KEY=$(openssl rand -hex 32) \
  -e NIGHTGATE_HTTP_PASSWORD=change-me \
  -v nightgate-data:/data \
  ghcr.io/odatano/nightgate:latest
```

The container targets Midnight preprod by default, serves with HTTP basic auth (`nightgate` / your password), persists its database in the `nightgate-data` volume, and proves in-process (WASM), so no proof server is needed to start.

Alternatively, any CAP app using the [`@odatano/nightgate`](/docs/nightgate/) plugin works, e.g. the NIGHTGATE repo itself via `npm run dev`.

## Configuration

Configuration is environment-driven, with the same connection variables as ODATANO-MCP: one ODATANO ACCESS key configures both servers, and a direct NIGHTGATE instance (local `cds watch`, an own deployment) is reached by pointing `ODATANO_ACCESS_URL` at it.

| Variable | Default | Purpose |
|----------|---------|---------|
| `ODATANO_ACCESS_KEY` | unset | The ODATANO ACCESS key `oda_…` from [api.odatano.dev](https://api.odatano.dev), sent as `Authorization: Bearer`. The same variable configures ODATANO-MCP. Against a direct instance: an `ngat_…` agent grant (`x-agent-token`, combinable with basic auth) or any other bearer |
| `ODATANO_ACCESS_URL` | `https://api.odatano.dev` | The gateway, or a direct NIGHTGATE host app (`http://localhost:4004` for `cds watch`) |
| `ODATANO_ACCESS_USER` / `ODATANO_ACCESS_PASSWORD` | unset | Basic auth against a direct instance (CAP dev / mocked auth); not for agents |
| `NIGHTGATE_SERVICE_PATH` | `/api/v1/nightgate` | OData service path |
| `NIGHTGATE_TIMEOUT_MS` | `30000` | Per-request timeout |
| `NIGHTGATE_SEED_HEX` | unset | Caller seed (64 or 128 hex) for `build_sponsorable_transaction`; never a tool argument. Needs `@odatano/nightgate-tx` installed |
| `NIGHTGATE_NETWORK` | `preprod` | Network the local builder targets (`preview`, `preprod`, `mainnet`) |
| `NIGHTGATE_INDEXER_HTTP_URL` / `NIGHTGATE_INDEXER_WS_URL` / `NIGHTGATE_NODE_URL` | public Midnight endpoints of the network | Indexer and node for the local builder |
| `NIGHTGATE_ZK_CONFIG_BASE_URL` | `<base url>/zk-config/attestation-vault` | Where the builder fetches prover keys (cached on disk in `NIGHTGATE_ZK_CACHE_DIR`) |
| `NIGHTGATE_PROOF_SERVER_URL` | unset | Prove contract circuits on a proof server instead of in-process WASM |

Through the gateway the key is the whole configuration. The server warns at startup when the gateway is the target and no key is set. Against a direct NIGHTGATE instance, create a scoped grant once as the operator (e.g. via `curl` against `createAgentGrant`) and hand the returned `ngat_…` token to the agent as `ODATANO_ACCESS_KEY`; the write tools are then limited to the grant's allowlist, budget and pinned session. The old names `NIGHTGATE_BASE_URL`, `NIGHTGATE_TOKEN`, `NIGHTGATE_USERNAME` and `NIGHTGATE_PASSWORD` are not read any more since 0.7.0.

## Use with Claude Code

```bash
claude mcp add nightgate \
  --env ODATANO_ACCESS_KEY=oda_... \
  -- npx -y @odatano/nightgate-mcp
```

Or in a project `.mcp.json` (Claude Code, Cursor and most MCP clients share this shape):

```json
{
  "mcpServers": {
    "nightgate": {
      "command": "npx",
      "args": ["-y", "@odatano/nightgate-mcp"],
      "env": { "ODATANO_ACCESS_KEY": "oda_..." }
    }
  }
}
```

For a local dev instance with mocked CAP auth: `ODATANO_ACCESS_URL=http://localhost:4004` and `ODATANO_ACCESS_USER` / `ODATANO_ACCESS_PASSWORD` instead of the key.

## Tools

### Verify

| Tool | What it does |
|------|--------------|
| `verify_attestation` | Live-state check that an attester's record of a payload hash stands in an AttestationVault. Named by `attesterId` + `payloadHash` or a bound `documentId`. Optional content-root / schema check, optional cross-network read |
| `verify_predicate` | Live-state check that a ZK claim was recorded true on-chain, id-free. `attesterId` + `payloadHash` name the record. Numeric predicates, `bytesEquality` (+ `expectedDigest`), `setMembership` (+ `setRoot`), `documentIntegrity` / `documentDiff` (+ `payloadHashB`) |
| `verify_predicate_attestation` | Verify a server-issued predicate attestation by its row id |
| `verify_document` | Verify an anchored document by document id + sha256 |

### Prove

| Tool | What it does |
|------|--------------|
| `prepare_document_proof` | Canonicalize a document into `payloadHash`, salted Merkle `contentRoot`, `schemaId`, per-field proof inputs with slot salts, and the full `opening` (synchronous) |
| `prepare_membership_set` | Build the canonical allow-list set tree: `setRoot` for verifiers, inclusion path for provers (synchronous) |
| `prove_field_predicate` | ZK proof that a hidden document field satisfies a threshold, without revealing it (async job) |
| `prove_field_equality` | ZK proof that a string field carries exactly the value behind a public digest (async job) |
| `prove_field_membership` | ZK proof that a hidden string field is one of a public allow-list, without revealing which (async job) |
| `prove_field_predicates_batch` | Up to 8 claims on one document in **one** transaction, any mix of numeric / equality / membership / cross-root kinds (async job) |
| `prove_document_integrity` | ZK proof that a second document differs from the anchored one only in a public slot mask, values hidden (async job) |
| `prove_document_diff` | ZK proof that two anchored documents differ at ≥ k slots, without revealing which (async job) |

### Anchor

| Tool | What it does |
|------|--------------|
| `anchor_document` | Anchor a document content hash on-chain as the session's own record, keyed by attester and hash. Returns `attesterId` and `documentId` (async job) |
| `attest_agent_output` | Anchor agent-output provenance as a canonical, third-party-verifiable envelope (async job) |

### Grant

| Tool | What it does |
|------|--------------|
| `grant_disclosure` | Grant a disclosure level (0 public, 1 legitimate interest, 2 authority) to a grantee identity. Attester-only (async job) |
| `revoke_disclosure` | Revoke a granted disclosure on-chain. Attester-only (async job) |

### Sponsoring

| Tool | What it does |
|------|--------------|
| `build_sponsorable_transaction` | Build, prove and sign an AttestationVault call locally with the seed from the server environment. Returns fee-unpaid bytes, unbound by default (synchronous, 20-60 s, needs `@odatano/nightgate-tx`) |
| `get_attester_identity` | The attester id this server builds under, derived from the seed (synchronous) |
| `sponsor_unbound_transaction` | Submit an unbound caller transaction. The sponsor binds, pays the dust and submits; several per sponsor wallet in parallel. `sponsorSessionId` may be the platform pool id (async job) |
| `sponsor_finalized_transaction` | Submit a transaction built, proven and signed elsewhere. The sponsor pays the dust, the effect carries the builder's identity. Serial per sponsor wallet (async job) |
| `derive_token_type` | Derive the raw token type a minting contract produces, from contract address + domain separator (synchronous) |

### Jobs

| Tool | What it does |
|------|--------------|
| `get_job_status` | Poll an async NIGHTGATE job until `succeeded` / `failed`. Sponsor jobs are polled with the `sessionId` the sponsor call returned |

Session-bound write tools (`anchor_document`, `prove_*`, `grant_disclosure`, `revoke_disclosure`) require a connected wallet session (`sessionId`); creating sessions stays outside MCP by design. Through the hosted gateway, agents write via the sponsoring tools instead.

## Typical agent flow

Through the hosted gateway, with `NIGHTGATE_SEED_HEX` set and `@odatano/nightgate-tx` installed:

```
1. get_attester_identity          → attesterId this server builds under
2. prepare_document_proof         → payloadHash, contentRoot, schemaId, opening, per-field inputs
3. build_sponsorable_transaction  → base64 bytes for call "anchorContentRoot"   (local, 20-60 s)
4. sponsor_unbound_transaction    → { jobId, sessionId }   (platform pool pays)
5. get_job_status                 → succeeded, on-chain tx
6. build_sponsorable_transaction  → "proveFieldPredicate", e.g. "carbon_footprint ≤ 80"
7. sponsor_unbound_transaction    → { jobId, sessionId }, then get_job_status
8. verify_predicate               → verified: true   (attesterId + payloadHash, anyone, crawler-free)
```

Against a direct instance with a wallet session (`sessionId`):

```
1. prepare_document_proof   → payloadHash, contentRoot, schemaId, per-field inputs
2. anchor_document          → { jobId }        (async)
3. get_job_status           → succeeded, attesterId, documentId
4. prove_field_predicate    → { jobId }        e.g. "carbon_footprint ≤ 80"
5. get_job_status           → succeeded, attestation id
6. verify_predicate         → verified: true   (attesterId + payloadHash, crawler-free)
```

## Errors

| Case | What the agent sees |
|------|---------------------|
| Attestation or proof absent | `verified: false` from every verify tool, never an error |
| 401 from the gateway | Key problem: missing, unknown or expired `oda_…` key |
| 402 from the gateway | Units exhausted. The error carries `unitsLeft`, `price` and the top-up hint |
| 403 from the gateway | Action not on the key. Agent grants, wallet sessions, deployment, dust registration and pool status are never reachable through the gateway |
| 429 from the gateway | Rate limited; `retryAfterSeconds` comes from `Retry-After` |
| Job `failed` with `CHAIN_EXECUTION_FAILED` | The transaction landed on-chain but the call did not apply (two calls on one contract in one block). Build again against current state and sponsor again. Never resubmit the same bytes |
| Job `reconciliation_required` | Broadcast outcome unknown to the server yet. The transaction id is in the error, the server keeps resolving it |
| `build_sponsorable_transaction` without package or seed | A clear error. Bytes built elsewhere with the txbuilder can still be handed to the sponsor tools |

## Stack

| Layer | Tech |
|-------|------|
| Protocol | Model Context Protocol (`@modelcontextprotocol/sdk`), stdio transport |
| Upstream | NIGHTGATE OData V4 (`/api/v1/nightgate`) via `@odatano/nightgate` ≥ 0.24.0, or the hosted ODATANO ACCESS gateway |
| Local builder | `@odatano/nightgate-tx` ≥ 0.6.0 (optional peer dependency, carries the Midnight SDK) |
| Chain | Midnight preprod on the hosted API; preprod / preview / mainnet on an own instance |
| Runtime | Node.js ≥ 20, TypeScript, `zod` schemas |
| Auth | ODATANO ACCESS key, `ngat_…` agent grant, basic auth or any other bearer |
| Tests | In-memory MCP client integration check (`npm run integration`), optional live round-trip, live sponsoring lane (`npm run live:sponsor-unbound`) |
