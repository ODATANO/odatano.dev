# Get Started

ODATANO is an OData V4 API for public blockchains: ODATANO for Cardano, NIGHTGATE for Midnight. Two ways in:

- **Hosted API:** one key at [api.odatano.dev](https://api.odatano.dev/), nothing to install. Start here.
- **Self-hosted:** run `@odatano/core` (Cardano) or `@odatano/nightgate` (Midnight) standalone, or add it to your CAP app as a plugin.

## Hosted API

Both services run hosted at [api.odatano.dev](https://api.odatano.dev/), behind one key. No node, nothing to install. Same OData routes as a self-hosted instance, on Cardano preprod and Midnight preprod.

| Product | Routes |
|---------|--------|
| ODATANO (Cardano) | `/odata/v4/cardano-odata`, `/odata/v4/cardano-transaction`, `/odata/v4/cardano-sign` |
| NIGHTGATE (Midnight) | `/odata/v4/nightgate`, `/odata/v4/nightgate-verify` |

### 1. Get a key

On the [console](https://api.odatano.dev/): sign in with a Cardano wallet (free start), buy a pack with ADA over x402, or redeem a code.

### 2. Call it

The key goes as a bearer token:

```bash
curl https://api.odatano.dev/odata/v4/cardano-odata/NetworkInformation \
  -H "Authorization: Bearer oda_..."
```

Address UTxOs and an unsigned ADA transfer, same paths as on a local plugin:

```bash
curl -X POST https://api.odatano.dev/odata/v4/cardano-odata/GetUTxOsByAddress \
  -H "Authorization: Bearer oda_..." \
  -H "Content-Type: application/json" \
  -d '{"address":"addr_test1..."}'

curl -X POST https://api.odatano.dev/odata/v4/cardano-transaction/BuildSimpleAdaTransaction \
  -H "Authorization: Bearer oda_..." \
  -H "Content-Type: application/json" \
  -d '{
    "senderAddress": "addr_test1...",
    "recipientAddress": "addr_test1...",
    "lovelaceAmount": 10000000
  }'
```

Every forwarded call is listed in the [API reference](https://api.odatano.dev/reference). The MCP servers ([ODATANO-MCP](/docs/odatano-mcp/), [NIGHTGATE-MCP](/docs/nightgate-mcp/)) take the same key as `ODATANO_ACCESS_KEY`; the gateway is their default URL.

## ODATANO on Cardano (in your CAP app)

`@odatano/core` exposes blocks, addresses, UTxOs and pools as OData entities and builds transactions as OData actions. Readable by SAP Fiori, Excel, Power BI or any OData client.

You need a SAP CAP project. If you do not have one yet:

```bash
npm i -g @sap/cds-dk
cds init my-app && cd my-app
```

### 1. Install

```bash
npm install @odatano/core @cap-js/sqlite
```

### 2. Configure

Add to your project's `package.json`:

```json
{
  "cds": {
    "requires": {
      "[development]": { "auth": { "kind": "dummy" } },
      "db": { "kind": "sqlite", "credentials": { "url": "db.sqlite" } },
      "odatano-core": {
        "network": "preview",
        "backends": ["blockfrost", "koios"],
        "blockfrostApiKey": "preview_your_api_key",
        "txBuilders": ["buildooor"]
      }
    }
  }
}
```

Get a free Blockfrost key at [blockfrost.io](https://blockfrost.io). All services are gated by `@requires: 'authenticated-user'`; the `[development] auth dummy` block lets local `cds watch` accept requests without a JWT. Persistent SQLite (`db.sqlite`) keeps the index cache across restarts. Full key reference: [Configuration](/docs/configuration/).

### 3. Run

```bash
cds watch
```

Three services auto-register:

| Service | Path |
|---------|------|
| `CardanoODataService` | `/odata/v4/cardano-odata/` |
| `CardanoTransactionService` | `/odata/v4/cardano-transaction/` |
| `CardanoSignService` | `/odata/v4/cardano-sign/` |

### 4. First requests

```bash
curl http://localhost:4004/odata/v4/cardano-odata/NetworkInformation

curl -X POST http://localhost:4004/odata/v4/cardano-odata/GetUTxOsByAddress \
  -H "Content-Type: application/json" \
  -d '{"address":"addr_test1..."}'

curl -X POST http://localhost:4004/odata/v4/cardano-transaction/BuildSimpleAdaTransaction \
  -H "Content-Type: application/json" \
  -d '{
    "senderAddress": "addr_test1...",
    "recipientAddress": "addr_test1...",
    "lovelaceAmount": 10000000
  }'
```

Go deeper: [User Guide](/docs/user-guide/), [Transaction Workflow](/docs/transaction-workflow/), [Plutus](/docs/plutus/).

## NIGHTGATE on Midnight (in your CAP app)

`@odatano/nightgate` does the same for **Midnight**: a block indexer plus a worker-thread wallet stack for ZK-aware transaction submission. Shielded transfers, Compact contracts and zero-knowledge attestations that prove a value meets a threshold without revealing it.

### 1. Install

```bash
npm install @odatano/nightgate @cap-js/sqlite
```

### 2. Configure

```json
{
  "cds": {
    "requires": {
      "db": { "kind": "sqlite" },
      "nightgate": { "network": "preview" }
    }
  }
}
```

### 3. Run

```bash
cds watch
```

Defaults to a public RPC node and a hosted indexer. Four services auto-register:

| Service | Path |
|---------|------|
| `NightgateService` | `/api/v1/nightgate` |
| `NightgateIndexerService` | `/api/v1/indexer` |
| `NightgateAnalyticsService` | `/api/v1/analytics` |
| `NightgateAdminService` | `/api/v1/admin` |

Submit actions are async: they return `{ jobId, status }`, then you poll `getJobStatus(jobId, sessionId)`. For wallet signing and submission you also run a local proof server:

```bash
docker compose -f docker/docker-compose.yml up -d proof-server
```

Go deeper: [NIGHTGATE](/docs/nightgate/), [NIGHTPASS](/docs/nightpass/).

## Run both together

The two packages are independent CAP requires. One app can serve Cardano and Midnight side by side:

```json
{
  "cds": {
    "requires": {
      "db": { "kind": "sqlite" },
      "odatano-core": { "network": "preview" },
      "nightgate": { "network": "preview" }
    }
  }
}
```

Then `cds watch`. All services from both packages register on their own paths.

## Standalone

The ODATANO repo runs on its own, without a CAP project of yours:

```bash
git clone https://github.com/ODATANO/ODATANO
cd ODATANO
npm ci
cp .env.example .env       # set BLOCKFROST_API_KEY, NETWORK, BACKENDS, TX_BUILDERS
cds deploy --to sqlite
cds watch
```

Server runs at `http://localhost:4004` with the same services. See [Docker Deployment](/docs/docker-deployment/) and [Production Deployment](/docs/production-deployment/) for running it as a service.
