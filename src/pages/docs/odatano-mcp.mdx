# ODATANO-MCP

`@odatano/core-mcp` is a **Model Context Protocol (MCP) server** that puts ODATANO, the OData API for Cardano, in front of AI agents. An agent reads chain, address, UTxO, asset, staking and governance data and queries the indexer with OData `$filter`. It builds transactions, hands them to a human or wallet for signing, verifies the signature and submits the CBOR. All of it through plain MCP tool calls. The agent needs to know nothing about OData, CBOR or the UTxO model.

It is the Cardano sibling of [NIGHTGATE-MCP](/docs/nightgate-mcp/) and makes the same promise: **the agent gets a notary, not a wallet.** Nothing in this server can sign. HSM signing (`SignWithHsm*`) and every admin operation (crawler and worker pause or resume) are deliberately not exposed. Wallet-worker jobs, where a server-held key signs, are opt-in.

## Why it is safe to let an agent build transactions

ODATANO's write path is Build, Sign, Submit. Signing happens outside the server. In the default flow the server never holds the sender's key. That sets what an agent may and may not do:

| Surface | Exposed? | Reason |
|---------|----------|--------|
| Reads (22 entities, 19 actions) | yes | Pure reads, cached by the indexer |
| `Build*` actions | yes | Return **unsigned** CBOR and a fee. Nothing moves without a signature the agent cannot produce |
| Signing handoff and verification | yes | Produces instructions for a human or CIP-30 wallet. Verifies, never signs |
| Submit | yes | The agent can only submit CBOR a wallet already signed |
| HSM signing | **never** | A server-held key is exactly the wallet the agent must not have |
| Wallet worker jobs (2.0) | opt-in | Server wallets sign. Off unless `ODATANO_MCP_ENABLE_WALLET_JOBS=1` |
| Admin (pause or resume crawler, worker) | **never** | Operator actions |

## Requirements

| Requirement | Version |
|-------------|---------|
| Node.js | ≥ 20. `npx` fetches the server, nothing to install |
| `@odatano/core-mcp` | 0.3.0 |
| Hosted API | Nothing else. One `oda_…` key from [api.odatano.dev](https://api.odatano.dev) |
| Own ODATANO host | `@odatano/core` ≥ 1.11.0; **≥ 2.0.0-rc.3 recommended** |

Hosts before rc.3 have two keyed-read defects. rc.1 drops `$expand` and `$select` on keyed reads; `get_transaction` works around it. Everything before rc.3 can answer a keyed read with a row the query excludes. That one has no workaround.

The tool catalogue depends on the host. At startup the server probes `cardano-worker/$metadata` and `cardano-indexer/$metadata`. A 1.x host and the hosted API get the 36 core tools. A 2.0 host adds four status tools for crawler and wallet worker. `ODATANO_MCP_ENABLE_WALLET_JOBS=1` adds the two wallet-job write tools, 42 in total.

## Getting an ODATANO instance

### Hosted API (default)

The default is the hosted ODATANO ACCESS gateway at [api.odatano.dev](https://api.odatano.dev). No node, no plugin, no wallet of your own. One `oda_…` key covers Cardano (this server) and Midnight (NIGHTGATE-MCP).

1. Get a key at [api.odatano.dev](https://api.odatano.dev). Sign in with a Cardano wallet (the first key comes with free calls), redeem a giveaway code, or buy a pack with tADA over x402 (`POST /keys`). The console shows the key once, together with a ready `.mcp.json`.
2. Put the key in your MCP client config as `ODATANO_ACCESS_KEY`. See [Use with Claude Code](#use-with-claude-code).

The gateway is the default URL. The server sends the key as `Authorization: Bearer`. The gateway swaps in the agent grant and meters the key per call. Metadata and service document lookups are free. The hosted ODATANO runs on Cardano **preprod** today.

Operator services (`cardano-worker`, `cardano-indexer`, agent grants) and HSM signing answer 403 on the gateway. The server registers none of them there. A 402 (units exhausted) reaches the agent with the top-up hint.

### Your own instance

Point `ODATANO_ACCESS_URL` at any ODATANO host app. The fastest way is the Docker image, published from the ODATANO repo on every release:

```bash
docker run -d --name odatano -p 4004:4004 \
  -e NETWORK=preview \
  -e BACKENDS=blockfrost,koios \
  -e BLOCKFROST_API_KEY=preview_xxx \
  ghcr.io/odatano/odatano:latest
```

Or any CAP app using the plugin: `npm i @odatano/core @cap-js/sqlite`, add `cds.requires.odatano-core`, `cds watch`. See [Get Started](/docs/get-started/). Then:

```bash
ODATANO_ACCESS_URL=http://localhost:4004
ODATANO_ACCESS_USER=alice            # CAP mocked auth, or an odat_… agent grant as ODATANO_ACCESS_KEY
```

## Configuration

| Variable | Default | Purpose |
|----------|---------|---------|
| `ODATANO_ACCESS_KEY` | unset | The credential. An ODATANO ACCESS key `oda_…` from [api.odatano.dev](https://api.odatano.dev), sent as `Authorization: Bearer`. The same variable configures NIGHTGATE-MCP. Against a direct instance: an `odat_…` agent grant (sent as `x-agent-token`) or any other bearer (XSUAA, `auth: jwt`) |
| `ODATANO_ACCESS_URL` | `https://api.odatano.dev` | The gateway, or a direct ODATANO host app (`http://localhost:4004` for `cds watch`) |
| `ODATANO_ACCESS_USER` / `ODATANO_ACCESS_PASSWORD` | unset | Basic auth against a direct instance (operator, CAP mocked or dev auth, e.g. `alice`). Not for agents |
| `ODATANO_SERVICE_PREFIX` | `/odata/v4` | Prefix before `cardano-odata`, `cardano-transaction`, `cardano-sign`, `cardano-worker`, `cardano-indexer` |
| `ODATANO_TIMEOUT_MS` | `30000` | Per-request timeout in milliseconds |
| `ODATANO_MCP_MAX_ROWS` | `50` | Default `$top` for `query_entity` and cap on arrays in tool output |
| `ODATANO_MCP_ENABLE_WALLET_JOBS` | `false` | Register `submit_wallet_job` and `cancel_wallet_job`. Server-managed wallets sign. Accepts `1`, `true`, `yes`, `on` |

## Use with Claude Code

```bash
claude mcp add odatano \
  --env ODATANO_ACCESS_KEY=oda_... \
  -- npx -y @odatano/core-mcp
```

Or in a project `.mcp.json`:

```json
{
  "mcpServers": {
    "odatano": {
      "command": "npx",
      "args": ["-y", "@odatano/core-mcp"],
      "env": { "ODATANO_ACCESS_KEY": "oda_..." }
    }
  }
}
```

The key is the whole configuration. The gateway is the default URL. For a local `cds watch` instance set `ODATANO_ACCESS_URL=http://localhost:4004` and `ODATANO_ACCESS_USER=alice`.

## Tools

36 core tools on every host, including the hosted API. Six more on a self-hosted ODATANO 2.0 host.

### Read

| Tool | What it does |
|------|--------------|
| `get_network_info` | Host network (mainnet, preview, preprod), current tip and backend health. Call this first |
| `get_latest_block` | Most recent block: hash, height, slot, epoch, time, tx count |
| `get_block` | Block by hash |
| `get_epoch` | Epoch by number, or the current one when omitted |
| `get_protocol_parameters` | Ledger parameters: fee coefficients, min-UTxO, max tx size, cost models, collateral percentage |
| `get_transaction` | Transaction by hash. `includeInputsOutputs` adds the resolved inputs and outputs |
| `get_transaction_metadata` | Metadata entries as `{ label, json }` (CIP-20, label 1447, CIP-25) |
| `parse_transaction_cbor` | Decode signed or unsigned CBOR. Pure, no network call, 128 KiB cap |
| `get_address` | Balance, native assets, stake address, tx count |
| `get_utxos` | UTxOs by address or by payment credential. Includes datums and reference scripts |
| `get_address_assets` | Native assets held by an address |
| `get_address_transactions` | Recent transactions touching an address, newest first |
| `get_asset_info` | Supply, mint and burn count, CIP-25 and CIP-26 metadata |
| `get_asset_history` | Mint and burn events, newest first |
| `get_account` | Stake account: controlled amount, rewards, pool and DRep delegation |
| `get_pool` | Stake pool: ticker, pledge, margin, stake, saturation |
| `get_drep` | Governance DRep: voting power, status, anchor, delegator count |

Lookups return `{ found: false }` as a clean negative rather than an error.

### Query

| Tool | What it does |
|------|--------------|
| `query_entity` | OData V4 query over the entity sets: `$filter`, `$select`, `$expand`, `$orderby`, `$top`, `$skip`, `$count` |

The entity sets are the indexer cache. Everything the `get_*` tools fetched before is in it. On a 2.0 host with the crawler, contiguously pre-synced blocks and transactions are in it too. Questions no fixed action covers become one call, e.g. transactions above 500 000 lovelace in the last 1 000 blocks. Numeric Int64 and Decimal fields come back as strings. Results are capped at `ODATANO_MCP_MAX_ROWS`; use `skip` to page.

Entities: 20 from the read service, 8 build and submission audit entities, 3 signing audit entities. A 2.0 host adds `WalletJobs`, `WorkerWallets`, `SyncState` and `ReorgLog`.

### Build — unsigned

| Tool | What it does |
|------|--------------|
| `build_ada_transfer` | ADA transfer. Optional assets, inline datum, lock at a script address, CIP-33 reference script |
| `build_metadata_transaction` | Transfer carrying transaction metadata, e.g. a CIP-20 message or a label-1447 anchor |
| `build_multi_asset_transfer` | Native assets plus ADA to one recipient |
| `build_mint_transaction` | Mint or burn under a Plutus V3 policy. Parameters, required signers, reference inputs, metadata, `__INPUT_IDX__` placeholders |
| `build_plutus_spend` | Spend a script UTxO: validator, redeemer, continuing datum, extra outputs, combined mint |
| `set_collateral` | Ensure an ADA-only collateral UTxO exists. Builds a self-send when missing |
| `get_build_details` | Re-fetch a build by id: CBOR, fee, status, inputs and outputs |
| `list_builds_by_address` | Build audit trail for a sender address |
| `derive_script_address` | Script address and hash for a validator, with optional parameters. Pure |
| `extract_payment_key_hash` | Payment credential hash of a bech32 address. Pure |

Every build returns `{ id, unsignedTxCbor, fee, … }`. **Nothing is signed or submitted.**

### Sign handoff, verify, submit

| Tool | What it does |
|------|--------------|
| `create_signing_request` | Turn a build into a signing request: instructions and a ready `cardano-cli` command for the human or wallet |
| `get_signing_request` | Request by id. State: `pending → verified → submitted` |
| `list_signing_requests` | Requests for a sender address, newest first |
| `verify_signature` | Check signed CBOR against its request: body, fee payer, required signers. No submit |
| `verify_data_signature` | CIP-30 `signData` (COSE_Sign1) verification for wallet login or consent |
| `submit_signed_transaction` | Submit signed CBOR, by `buildId` or raw with `network`. A duplicate returns `alreadySubmitted: true` |
| `submit_verified_transaction` | Verify and submit for a signing request. `deferSubmit` returns before the network submit |
| `get_submission_status` | Submission state. `refresh` re-checks the chain |

### ODATANO 2.0 subsystems

**Not available on the hosted API.** Registered only when a self-hosted 2.0 host serves `cardano-indexer` and `cardano-worker`.

| Tool | Service | What it does |
|------|---------|--------------|
| `get_sync_status` | indexer | Crawler status: sync state, last indexed slot, tip height, progress |
| `get_reorg_log` | indexer | Chain reorganisations handled by the crawler, newest first |
| `get_worker_status` | worker | Wallet worker: running flag, wallet ids, in-flight jobs, queue depth |
| `get_wallet_job_status` | worker | Job lifecycle from pending to confirmed or failed: tx hash, fee, error |
| `submit_wallet_job` | worker | **Opt-in.** Queue a job a server-managed wallet builds, signs, submits and confirms. This moves funds |
| `cancel_wallet_job` | worker | **Opt-in.** Cancel a job that has not started building |

The two write tools need `ODATANO_MCP_ENABLE_WALLET_JOBS=1`. Use them with a scoped credential only.

## Typical agent flow

```
1. get_network_info            → which network am I on?
2. get_utxos(address)          → what can be spent?
3. build_ada_transfer(...)     → { id, unsignedTxCbor, fee }   (nothing moved)
4. parse_transaction_cbor      → show the human what they are about to sign
5. create_signing_request      → instructions + cardano-cli command
   … human / CIP-30 wallet signs …
6. verify_signature            → witnesses valid for fee payer + required signers
7. submit_signed_transaction   → { txHash, status }
8. get_submission_status       → confirmed
```

## Errors

Upstream OData errors surface as tool errors with `{ httpStatus, code, message }`. Codes include `ODATANO_INVALID_INPUT`, `ODATANO_NOT_FOUND`, `ODATANO_INSUFFICIENT_FUNDS`, `ODATANO_TX_VALIDATION_FAILED`, `ODATANO_PROVIDER_UNAVAILABLE` and `ODATANO_PROVIDER_RATE_LIMITED`. The agent can react instead of failing blind: 401 means credentials, 429 means back off, 400 means fix the arguments.

On the hosted API a 402 means the key's units are used up. The error carries the top-up hint. A 403 is a service the gateway keeps closed.

Long arrays are capped at `ODATANO_MCP_MAX_ROWS`. Large CBOR blobs nested in results are elided. Tools whose job is returning CBOR keep it.

## Stack

| Layer | Tech |
|-------|------|
| Package | `@odatano/core-mcp` 0.3.0 |
| Protocol | Model Context Protocol (`@modelcontextprotocol/sdk`), stdio transport |
| Upstream | ODATANO OData V4, five services under `/odata/v4` |
| Chain | Cardano mainnet, preview or preprod, whatever the host targets. Hosted API: preprod |
| Runtime | Node.js ≥ 20, TypeScript, `zod` schemas |
| Auth | ODATANO ACCESS key as bearer. `odat_…` agent grant as `x-agent-token`. Basic auth for dev instances |
| Tests | Unit tests, an in-memory MCP client integration check, optional live round-trip on preview |
